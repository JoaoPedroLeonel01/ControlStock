# ControlStock - E-commerce Inventory Management System

ControlStock is an inventory management backend system designed specifically for apparel (clothing) e-commerce businesses. It provides transactional inventory control, clothing variation matrices (Size/Color/SKU), stock reservation workflows, and financial valuation.

Designed with a dual purpose:
1. **Software Engineering Showcase:** Clean architecture, strict domain modeling, ACID transactions with concurrency locks, automated tests, and CI/CD pipelines.
2. **Production-Ready Foundation:** Practical, battle-tested domain logic tailored for clothing retail operations.

## Key Features (MVP)

- **Clothing Matrix Catalog:** Parent products with variant combinations (reusable size grids with letters or numbers, Colors/Prints, per-product price tiers with price history, and auto-generated SKUs).
- **Three-Tier Stock Levels:** Real-time tracking of `Physical`, `Reserved`, and `Available` (`Physical - Reserved`) quantities.
- **Stock Reservation Engine:** 10-minute temporary reservation window for PIX checkout, with instantaneous settlement for credit/debit cards.
- **Zero-Negative Guarantee:** Database-level check constraints preventing negative stock quantities under any circumstance.
- **Immutable Inventory Ledger:** Audit trail tracking every inbound batch, outbound order, customer return with mandatory reason, and physical adjustment.
- **Reporting & Alerts:** Low-stock threshold alerts, valuation reports (total invested cost vs. potential retail revenue), and category/status filtering.

## Local Development

```bash
# 1. Environment variables (DATABASE_URL is required)
cp .env.example .env

# 2. Python dependencies (runtime + dev tools: pytest, ruff, httpx)
python -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt

# 3. Start PostgreSQL 16
docker compose up -d postgres

# 4. Apply database migrations
alembic upgrade head

# 5. Run the API
uvicorn src.control_stock.main:app --reload
```

### Database Migrations (Alembic)

Migration scripts live in `migrations/versions/`. New revisions are automatically
linted and formatted by Ruff (post-write hooks in `alembic.ini`).

```bash
alembic revision --autogenerate -m "create products table"  # generate from models
alembic upgrade head        # apply all pending migrations
alembic downgrade -1        # revert the last migration
alembic check               # fail if models and migrations are out of sync
```

> Always review autogenerated migrations before committing. New models must be
> imported in `migrations/env.py` to be detected by autogenerate.
